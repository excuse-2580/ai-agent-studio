# 在手机上本地跑模型（不依赖电脑）

让模型直接在你的安卓手机里推理。数据不出手机，断网也能聊。

## 先搞清楚一件事

**PWA（浏览器）方案做不到，必须用 APK。**

原因是 `127.0.0.1` 指的是"你自己这台设备"：

- 用 **APK**：界面就在手机里，它访问 `127.0.0.1:8080` 访问的正是手机上 Termux 的服务 → ✅ 通
- 用 **PWA 连电脑**：页面跑在电脑上，它访问 `127.0.0.1` 找的是电脑自己，永远够不到手机 → ❌ 不通

所以要先[编译安装 APK](./README.md#方式三让-github-云端帮你编译-apk不用装-android-studio)，或者按 README 里的方式二本地编译。

## 整体链路

```
手机里的 APK（界面）  ──http://127.0.0.1:8080──▶  手机里的 Termux（llama.cpp 跑 .gguf）
```

Termux 和别的 App 共享同一个网络栈，所以 App 访问 `127.0.0.1` 能直接到 Termux 起的服务。

## 最快路径：一键脚本

### 1. 装 Termux

**只从 F-Droid 或 GitHub Releases 装**，别用 Google Play 上的版本（已停止维护，会有各种怪问题）。

- F-Droid：https://f-droid.org/packages/com.termux/
- 或直接下 APK：https://github.com/termux/termux-app/releases

### 2. 粘贴一行命令

打开 Termux，粘贴：

```bash
bash <(curl -sL https://raw.githubusercontent.com/excuse-2580/ai-agent-studio/main/tools/termux-setup.sh)
```

脚本会一步步带你走：选方案 → 装依赖 → 挑模型 → 下载 → 编译 → 启动 → 自检。全程有中文提示。

想跳过交互直接选：

```bash
# Ollama 模式（免编译，几分钟）
bash <(curl -sL .../termux-setup.sh) --ollama

# llama.cpp 模式（源码编译）
bash <(curl -sL .../termux-setup.sh) --llamacpp
```

### 3. 在 App 里填地址

```
模型 → 添加模型源
  类型：本地模型 · llama.cpp (GGUF)
  地址：http://127.0.0.1:8080/v1
  密钥：留空
  模型：脚本跑完会告诉你（一般是 local-model）
```

点「测试连接」，看到 ✅ 就能聊了。

## 模型怎么选

| 模型 | 体积 | 内存要求 | 体验 |
|---|---|---|---|
| Qwen2.5-1.5B Q4_K_M | ~1GB | 4GB+ | **首选**，中文好，短问答、翻译、润色够用 |
| Llama-3.2-1B Q4_K_M | ~0.8GB | 4GB+ | 最快，英文强 |
| Qwen2.5-3B Q4_K_M | ~2GB | 8GB+ | 旗舰机可用，长文本会明显变慢 |
| 7B 及以上 | 4GB+ | 12GB+ | 能加载，但慢到几乎没法聊天，不推荐 |

量化统一选 **Q4_K_M**，体积和质量的甜点。

## 真实速度预期

别拿手机跟电脑比。手机没有独立显存（和 system 共用内存），也没有风扇，SoC 发热会降频。

实测参考（骁龙 855 / 865 级别）：

- 1.5B 模型：约 8-12 token/秒，日常问答流畅
- 7B Q4：约 4-5 token/秒，能读但明显等
- 连续跑几分钟后，速度会因发热肉眼可见地掉

**手机是 1B-3B 的舞台，7B 以上留给电脑。** 适合"问一句答一句"的短交互。

## 四个必须做的设置（不做一定出问题）

1. **Termux 电池策略设为「无限制」**
   系统设置 → 应用 → Termux → 电池 → 无限制。否则锁屏就被杀，服务断开。

2. **多任务界面把 Termux 锁住**
   从底部上划进入多任务，长按 / 下拉 Termux 卡片加锁，防止后台清理。

3. **编译只在家目录 `~` 里做**
   `/sdcard` 等外部存储不给加执行权限，在那儿编译必然报 `Permission Denied`。一键脚本已经帮你处理了。

4. **插电 + 通风**
   编译和推理都很吃 CPU，手机会发烫。拆掉手机壳，别放被子上。

## 开机自启（可选）

装 [Termux:Boot](https://f-droid.org/packages/com.termux.boot/) 后，脚本已经写好
`~/.termux/boot/start-aas.sh`，开机自动拉起服务并申请唤醒锁。

## 手动方案（想自己掌控每一步）

```bash
# 换镜像（下载慢就换）
termux-change-repo

# 装依赖
pkg update && pkg upgrade -y
pkg install -y git cmake clang make wget libandroid-spawn

# 编译（必须在 ~ 下）
cd ~
git clone --depth 1 https://github.com/ggml-org/llama.cpp.git
cd llama.cpp
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release -t llama-server -j4

# 下模型（国内访问不了就换 hf-mirror.com）
wget https://hf-mirror.com/Qwen/Qwen2.5-1.5B-Instruct-GGUF/resolve/main/qwen2.5-1.5b-instruct-q4_k_m.gguf

# 起服务
./build/bin/llama-server -m ~/qwen2.5-1.5b-instruct-q4_k_m.gguf \
  --host 127.0.0.1 --port 8080 -c 2048 -t 4 -ngl 0
```

`libandroid-spawn` 容易漏装，缺了会报 `spawn.h not found`。

## 不想折腾？

Termux 里直接装 Ollama 更省事：

```bash
pkg install ollama
ollama serve &
ollama run qwen2.5:1.5b
```

或者干脆装现成的 GUI App：**PocketPal AI**（开源，内置模型商店，支持任意 GGUF）、
**Google AI Edge Gallery**（谷歌出品）、**MLC Chat**（走 GPU，速度最快）。

代价是：那些 App 有自己的界面，不跟你这个 App 的智能体设定打通。想用自己的智能体设定，
还是得走 Termux + 本 App 这条路。

## 常见问题

**测试连接失败？**
先看服务活着没：Termux 里 `curl http://127.0.0.1:8080/v1/models`。
能返回 JSON 就是服务正常，问题在 App 端地址写错；没返回就是服务没起来，看 `tail -50 ~/aas-local/server.log`。

**模型加载很慢？**
首次加载 1GB 模型要 30-60 秒属正常，等它加载完再测。

**跑一会就断了？**
就是电池优化 / 后台清理的问题，回去看"四个必须做的设置"。

**HuggingFace 下载不动？**
把链接里的 `huggingface.co` 换成 `hf-mirror.com`。一键脚本会自动回退重试。
